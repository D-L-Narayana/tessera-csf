# QA, CI and deployment checks

How Tessera's build output, production headers and browser workflows are verified, and what each check means.
The scripts live in `qa/` (operator notes in `qa/README.md`); the configuration tests live in `tests/deploy.test.ts`.

## What is deployed

A static `dist/` built by `npm run build` (`tsc` + `vite build`, `base: './'`) and served by Vercel with the
headers declared in `vercel.json`:

| Header | Value |
|---|---|
| `Content-Security-Policy` | `default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' data: blob:; font-src 'self'; connect-src 'self'; manifest-src 'self'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'; object-src 'none'` |
| `Strict-Transport-Security` | `max-age=63072000; includeSubDomains` |
| `X-Content-Type-Options` / `X-Frame-Options` / `Referrer-Policy` | `nosniff` / `DENY` / `no-referrer` |
| `Permissions-Policy` | `camera=(), microphone=(), geolocation=(), payment=(), usb=()` |
| `Cross-Origin-Opener-Policy` / `Cross-Origin-Resource-Policy` | `same-origin` / `same-origin` |
| `Cache-Control` | `public, max-age=31536000, immutable` for `/assets/(.*)` (content-hashed); `no-cache` for `/` and `/index.html` |

`style-src` has no `'unsafe-inline'`: the UI never uses `style=` attributes, `<style>` injection or
`dangerouslySetInnerHTML`, and width-proportional visuals are SVG numeric attributes or `<meter>`. `check-dist`
and the UI tests keep it that way. The Vite dev server and `vite preview` do not apply these headers.

## The four steps

### 1. Build-output gate — `node qa/check-dist.mjs`

Runs in CI after `npm run build` and fails (exit 1) when `dist/index.html` contains an inline `<script>`, a
`<style>` element, a `style=` attribute, an inline event handler or a `<base>` element; when an asset URL is not
relative (`./…`) or points at a missing file; when the gzip total of `dist/assets/*.js` exceeds the budget
(`BUDGET_JS_GZIP_KB`, default 120); when `dist/THIRD_PARTY_LICENSES.txt` is missing; when a published schema in
`dist/schemas/` does not parse; when a relative `url()` in a stylesheet (the self-hosted fonts) does not resolve;
or when a `data:` URL in CSS would be blocked by the production CSP. It reports, without failing, the `data:` URLs
it finds per MIME type and prints a summary table.

### 2. Serve with the production headers — `node qa/serve-dist.mjs --port 6120`

A dependency-free server for `dist/` that reproduces Vercel's behaviour: every `headers` rule from `vercel.json`
whose `source` matches the path is applied (later rules win per header), `cleanUrls` semantics (`/` → `index.html`,
`/name` → `name.html`, `/name.html` → 308), correct MIME types, HEAD support, 404 for anything outside `dist/`.
The headers cannot be relaxed, so the browser checks below measure the real policy.

### 3. Browser workflow under the enforced CSP — `node qa/workflow.mjs`

Needs a Playwright library (not a repo dependency; see "Running the browser scripts"). It drives the built app at
1440 px, then 375 px, and writes `qa/screens/workflow-results.json`, `qa/screens/headers.json` and screenshots
`01…09`. Beyond the original 16 checks (default contradicted outcome, deep link, stale remediation, add evidence →
partial → sufficient, refused then accepted not-applicable, import rejection, CSV/JSON export, empty profile,
keyboard selection, console errors, mobile overflow) it exercises the 0.2 workflows with the UI strings documented
in the feature pages:

- **Drawer** — `Edit EV-004` → `Save changes`; `Remove EV-004` raises a `confirm` dialog (recorded); `Undo` restores it.
- **Horizon** — `Horizon (days)` 60 omits EV-003, 90 lists it (the MFA export turns aging on 2026-12-22).
- **Compare** — the just-exported report imported in *Compare with a previous report* yields "… 25 unchanged".
- **Rule policy** — `Minimum override rationale (characters)` = 10 turns GV.PO-01's "Looks fine." override valid
  (`sufficient`), the `custom policy` badge appears, `Reset to defaults` reverts both.
- **Gap register & Summary** — `Function` = GV filters to GV outcomes; the *Summary* heading has an accessible visual.
- **Exports** — real downloads: Markdown summary (last line `Generated by Tessera (educational prototype) …`),
  gap-register CSV (rows = gaps + 1), evidence-inventory CSV (rows = artifacts + 1), pack and report JSON.
- **Session** — `Keep this session in this browser` writes `tessera.session/1` only after opt-in; `Forget saved session` clears it.
- **Theme** — dark emulation changes the page background (`08-dark.png`); print emulation hides the pack actions (`09-print.png`).
- **Policy and network evidence** — `document.fonts.check('12px Fraunces')` is true and no font face errors under
  `font-src 'self'`; zero `securitypolicyviolation` events (listener installed with `addInitScript`) and zero
  "Refused to …" console lines; every request goes to the served origin; no failed requests.
- **Headers** — the `/` response carries a CSP byte-equal to `vercel.json`, nosniff, DENY, no-referrer, HSTS and
  `no-cache`; the first `/assets/*.js` and `*.css` responses have the right `Content-Type`, the same CSP and
  `immutable` caching; a `/assets/*.woff2` response is `200 font/woff2`.

Exit 1 on any failed check; the JSON lists every check with `pass` and a short `detail`.

### 4. Accessibility audit — `node qa/axe-audit.mjs`

axe-core with the `wcag2a`, `wcag2aa` and `wcag21aa` tags at 1440 / 768 / 375 for each path in `--paths`
(default `/` and `/#/RC.CO-03`), optionally with `--dark`. Each entry in `<out>/browser-audit.json` has the same
shape as the earlier audits (`name, status, url, errors, failedRequests, layout, violations, incompleteChecks`)
plus `path`, `colorScheme`, `context`, `engine`, `axeVersion`, `tags` and `horizontalOverflow`. Exit 1 when any
violation, page error or horizontal overflow is found.

**CSP-enforced vs. axe-instrumentation.** axe has to inject its own script into the page, which the production
CSP (`script-src 'self'`) forbids. The audit therefore opens each page in a browser context created with
`bypassCSP: true` and labels every entry
`"context": "axe-instrumentation (bypassCSP: true; application CSP unchanged on the server)"`. Nothing is changed
on the server, and the workflow script — which never bypasses the CSP — is the evidence that the application runs
under the enforced policy. The two results should be read together.

**Engine paths.** With `@axe-core/playwright` available the entry records `"engine": "@axe-core/playwright"`.
Without it, pass `--axe-source <path to axe-core/axe.min.js>`: the file is injected with `page.addScriptTag`,
`window.axe.run(document, { runOnly: { type: 'tag', values: [...] } })` is evaluated, and the entry records
`"engine": "axe-source: axe.min.js"` with `axeVersion` from `window.axe.version`. When neither is available the
script exits 2 with instructions.

## Running the browser scripts

Playwright and axe are deliberately not dependencies of this repository (two runtime dependencies is a documented
strength). Install them once in a scratch directory and expose them through `NODE_PATH`; browsers come from
Playwright's default cache or `PLAYWRIGHT_BROWSERS_PATH`:

```bash
mkdir -p ../qa-tools && (cd ../qa-tools && npm init -y >/dev/null && npm i playwright @axe-core/playwright)
(cd ../qa-tools && npx playwright install chromium)        # unless PLAYWRIGHT_BROWSERS_PATH already provides it
export NODE_PATH=$PWD/../qa-tools/node_modules

npm run build && node qa/check-dist.mjs
node qa/serve-dist.mjs --port 6120 &
node qa/workflow.mjs  --url http://127.0.0.1:6120/ --out qa/screens
node qa/axe-audit.mjs --url http://127.0.0.1:6120/ --out qa/audit
node qa/axe-audit.mjs --url http://127.0.0.1:6120/ --out qa/audit-dark --dark
```

Both browser scripts exit 2 (not 1) when the library or the browser is missing, so an environment problem is never
mistaken for a failing application.

## Continuous integration

`.github/workflows/verify.yml` runs on every push to `main`, every pull request and on demand, on a Node `'20'` and
`'22'` matrix: `npm ci --no-fund` → `npm run typecheck` → `npm test` → `npm run build` → `node qa/check-dist.mjs` →
`npm audit --audit-level=high`. Permissions are `contents: read`, actions are pinned to commit SHAs, and a
`verify-<ref>` concurrency group cancels superseded runs.

## What the configuration tests guard — `tests/deploy.test.ts`

- `vercel.json`: `default-src 'none'`, `script-src 'self'`, `style-src 'self'`, no `unsafe-inline`/`unsafe-eval`
  anywhere, `frame-ancestors`/`object-src`/`base-uri`/`form-action` all `'none'`, nosniff/DENY/no-referrer/HSTS,
  immutable caching for `/assets/(.*)`, `no-cache` for `/` and `/index.html`, rule order.
- `qa/serve-dist.mjs`: `source` matching, header resolution (`/index.html` → CSP + no-cache; `/assets/x.js` →
  CSP + immutable), MIME types, cleanUrls, traversal attempts answered 404, HEAD, 405 for other methods.
- `qa/check-dist.mjs`: each finding on crafted `index.html` samples, data: URL counting, CSP source matching,
  pass/fail behaviour of `runChecks` on temporary dist directories.
- `verify.yml`: every `uses:` pinned to a 40-hex SHA, read-only permissions, the Node matrix, step order.
- Portability: no private paths or placeholders in `qa/*.mjs` and these documents; `bypassCSP: true` appears only in
  `qa/axe-audit.mjs`, together with the instrumentation label and the `--axe-source` fallback.

All of this is verification tooling for an educational prototype on synthetic data; passing checks are not a
certification, attestation or compliance conclusion.
